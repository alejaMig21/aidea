# 2026-11-04

### 00:00 · pivot · Everything becomes a plugin

After seeing DeepSeek's harness, the person decided aidea should keep its philosophy (layers, Contract, Tutor) but open up: a small kernel and everything else a plugin on one versioned API (ADR 0008). A spec of 65 stories and 17 tickets followed.

**Why it matters:** aidea stops being a closed box and becomes a platform others can extend.
**Evidence:** `docs/adr/0008-a-small-kernel-and-everything-else-is-a-plugin.md` · `.scratch/plugin-system/spec.md`
**In their words:** "todo debe ser un plugin"

### 03:00 · milestone · The plugin system works end to end

While the person slept, all 17 tickets were built test-first: loader, Panel slot, quarantine with a scan, install after confirming each blocking finding, enable/disable/remove, versions and dependencies, guard rules, events, safe mode and an emergency screen, updates shown as a difference, settings forms with secrets kept out of files, live inspection plus a template and a skill so the Builder can write and propose a plugin, a read-only Tutor tool, and a test tool for plugin authors. Suite: 790 tests, 0 failing. Checked live in Electron (16 of 16, then 17 of 17).

**Why it matters:** the Builder can now write a plugin and the person decides in a manager screen.
**Evidence:** commits `f1c3869` to `4951a98` · `.scratch/plugin-system/live-shots2/`

### 03:30 · surprise · Live checks found what tests did not

A plugin whose folder sat under a package.json without `"type":"module"` failed only in the real app; the host now writes its own. Also: the default secret store is in memory, because the core runs as a child process of Electron and cannot reach its secure store.

**Why it matters:** an honest gap is written down instead of hidden.
**Evidence:** commit `188921c` · `.scratch/plugin-system/issues/13-settings-data-and-secrets.md`

### --:-- · milestone · Play starts the whole project

Play became a plugin: a run recipe in `.aidea/run.json`, the person's consent tied to the exact recipe, an ordered start that waits for each part's ready signal, Stop and restart with dependents, and the output of each part in its own Terminal tab. Checked live in Electron, 11 of 11.

**Why it matters:** a person can press one button and see the database, the backend and the frontend come up in order.
**Evidence:** commits `77ebd0f`, `6757c86` · `.scratch/run-and-terminal/issues/`

### --:-- · milestone · Run and terminal, tickets 08 to 13

Environment variables are listed by name and read only from the project's own `.env` (a missing one is named). Closing aidea while parts run asks first and stops every part: killing the core on Windows did not run the plugin's cleanup, so parts would have been left behind. The Builder proposes the recipe with a tool, and the core refuses any ready signal that no cited file shows. Text selected in the terminal takes an 8000 character limit and keeps its end; "Fix" and "Explain and fix" hand it to the Builder as data under the Contract; anything that looks like a secret asks first. Suite: 864 tests, 0 failing. Checked live in Electron except the parts that call a real model (Explain, Fix, the Builder proposing a recipe).

**Why it matters:** an error in the terminal goes to the Tutor or the Builder in two clicks, without copy and paste and without a secret leaving by accident.
**Evidence:** commits `2cc5d97`, `a72d318`, `65fed81`, `d565dbb`, `13bcd6f`, `35cb0fb` · `assets/2026-11-04-terminal-selection.png`

### --:-- · pivot · The look has to feel like a place developers already know

After the live checks the person judged two screens: the confirmation before Play ran commands, and the plugin list. They pointed at VS Code's Extensions view as the model and left it open on the second monitor. Plugins now show as an extensions list (search, counted sections, an icon, name, one line, publisher), and the confirmation is a dialog of aidea's own with the commands in monospace and the safe button focused first.

**Why it matters:** trust comes from familiarity: a person who knows VS Code reads the plugin list without learning anything.
**Evidence:** commit `d471677` · `docs/agents/ui-style.md` · `assets/2026-11-04-plugin-manager.png` · `assets/2026-11-04-play-dialog.png`

### --:-- · problem · An accepted recipe would have been offered for deletion

The guard that watches `.aidea/` for changes made without a Proposal also watched `run.json`. If the person accepted a recipe while the Builder's turn was still running, the file appeared and the chat would say "Claude changed an authored file", with a Restore button that deletes the recipe just accepted. The recipe is protected by the consent hash instead (a changed recipe makes Play ask again), so the guard now skips it.

**Why it matters:** two safety mechanisms disagreed, and the one that was meant for something else would have undone the person's own decision.
**Evidence:** commit `1754064` · `test/authored-guard.test.ts`

### --:-- · pivot · Class mode, Direct mode and the decision classes are removed

Two modes decided how the Builder treated a change the person had not asked for, and a card asked about every decision. They were removed: the Builder follows the Contract and invents nothing, and a change the Contract does not hold is a Proposal the person accepts. The Tutor's teaching of each decision went with them.

**Why it matters:** one rule instead of three, and the person's agreement (the Contract) is the only thing the Builder has to read.
**Evidence:** commits `58d676d`, `4ab0a44`, `39a5dc7` · `.scratch/ticket-audit-2026-11-04.md`

### --:-- · milestone · The Data layer: variables, then linked structures, then polish

Data draws the variables of a function that was played: scalars, lists with their places, dictionaries, and marks what changed at each step, following Playback and Flow. Then objects that point to objects (lists, trees, cycles, aliases) became nodes and arrows, with a pointer set by the last step marked NEW and the old arrow dashed. The last pass added each value as text beside the drawing, a button to save the drawing as an SVG, and named lists of numbers for Run (empty, random, sorted, nearly sorted, many duplicates).

**Why it matters:** the first time the person can watch the memory of a program, not only its lines.
**Evidence:** commits `195397e`, `9eac9b3`, `59ae362` · `.scratch/layout-and-data/`
