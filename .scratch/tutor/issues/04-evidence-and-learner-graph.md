# 04: Evidence and the Learner graph

**What to build:** What the person does in a class is recorded in two places under the user's aidea folder, outside any Project. Evidence: an append-only ledger with one entry per answer (class, question, correct or not, confidence, the free text, time). Learner graph: append-only line-oriented files of Propositions (name, statement, aliases, provenance: class and message, and the Project Node when relevant) and Reasoning chains (premises, conclusion, provenance). At the end of a class a pipeline builds the graph from the Teacher's prose only: an Extractor session proposes Propositions and chains, an Auditor session finds duplicates and near-duplicates, and a deterministic program that uses no model is the only writer: identifiers are derived from the normalised name, so the same input gives the same graph. The person's answers never enter the graph. A route lists what has been recorded; an idea can be deleted together with its chains but not edited. A class is not closed until the pipeline has run; if it fails the class stays open for retry and nothing is half written.

- Formats. `evidence.jsonl`: one object per answer `{classId, questionId, project, kind, correct, confidence, answer, thought, dontKnow, time}`; `correct` is true/false only for a choice answered, null for text answers and for dontKnow (nothing graded or demonstrated). `propositions.jsonl` / `chains.jsonl`: `{"op":"put","proposition"|"chain":{...}}` (whole record, last put for an id wins) and `{"op":"delete","id"}` tombstones; the pipeline appends only records that changed, so a rerun appends nothing. Ids: normalised name with spaces as `-`; chains `ch-` + 12 hex of sha1 over sorted premise ids and the conclusion. `pending-<classId>.json` holds the Teacher prose of a class whose pipeline has not succeeded (atomic rename; removed on success).
- Routes: `GET /learner/graph`, `GET /learner/evidence?project=&class=`, `DELETE /learner/propositions/<id>`, `POST /tutor/classes/<id>/close` (retry: 200 `{ok,ideas}`, 404 nothing waiting, 409 running, 502 `pipeline failed`). The class stream ends with `{type:"learner", classId, status:"saved", ideas}` or `{status:"failed", message}` (not sent if the Teacher said nothing). `POST /tutor/classes` accepts an optional `node` stored in provenance. Defaults: `~/.aidea/learner` or `AIDEA_LEARNER_DIR` (main.ts); `startCore({learnerDir, learnerModel})`, model default `haiku`; without `learnerDir` everything stays in memory.
- Choices to review: any record not matching the schema rejects the whole Extractor output (class stays retryable); the Extractor gets the prose as numbered messages (0-based) and returns the message number per record; the whole class goes in one Extractor call (no chunking; about 3,000 words measured as one cheap call in the spike, but a very long class is untested); a chain that concludes one of its own premises (e.g. after an Auditor merge) is dropped; the person ending the class while the pipeline runs still finishes it on the server, the interface just may not hear the result (the pending file lets a retry find it).
- NOT verified with a real model: the real Extractor and Auditor prompts and schemas (only the launch flags through a fake spawn and `structured_output` parsing), the quality of extracted ideas, and passing a JSON schema on the Windows command line. UI: the "Saved N ideas" line and Retry button are not checked in a browser.
