# 05: The teach loop: predict, one fact, check, repair

**What to build:** A class teaches in steps. For the next untaught step of the Plan (until ticket 07 exists: of a topic the person names), the Teacher first asks the person to predict, in a turn of its own and open-ended; then explains one fact, opening by resolving the prediction; then checks with a multiple-choice or free-text question whose correct answer was fixed before it was shown. A wrong check is diagnosed and re-taught before the next step; a right check moves on. Confidence and "what I thought" are recorded as Evidence (ticket 04). The Teacher's instructions are written for aidea and say these rules in plain positive terms; they are not copied from LearnHarness.

**Blocked by:** 02, 04

**Status:** ready-for-agent

- [x] Through the protocol with a scripted Teacher: a predict question is posed before the explanation tool is accepted for that step (the order is enforced by the core, with an error the model can act on otherwise).
- [x] A check is rejected if it has no committed correct answer.
- [x] A wrong check keeps the step open: the next step is refused until a re-teach and a correct check, and each attempt is Evidence.
- [x] Free-text answers are graded by a model call against the committed answer, tested with a scripted grader.
- [x] The class can be ended by the person at any moment and the pipeline of ticket 04 still runs on what was taught.
- [x] A short live run against the real Claude Code is recorded in the ticket's review notes (a manual script, not an automated test).

- [x] Tools (Tutor role, `TUTOR_TOOLS` in `src/core/tutor.ts`; order and state in `src/core/teach.ts`): `begin_step {stepId,title}`, `predict {stepId,prompt}`, `explain {stepId,text}`, `ask {stepId,kind,prompt,options|correct|expected,allowDontKnow}` (the check), `finish_class {summary}`. Finish it before beginning another step.`, `Step "s1" has no prediction yet. - [x] Step states: new, predicted (prediction answered), explained, missed (wrong check or don't know), closed. A wrong check keeps the step open; begin_step is refused until a new `explain` (marked `repair: true` in the `tutor_explain` event) and a right check. `finish_class` is refused while a step is open or when no step was taught.
- [x] Events added to the class stream: `tutor_step {stepId,title}`, `tutor_explain {stepId,text,repair}`, `tutor_finished {summary}`; `tutor_question` carries `stepId` and `phase` ("predict" or "check"). The committed answer is still never sent.
- [x] Evidence: every prediction and check attempt is an entry with `stepId`, `phase`, `attempt`; `sureAndWrong: true` only for a wrong choice with confidence 70 or more (also told to the Teacher in the check result, with an instruction to repair the misconception first). Text checks: `correct` is the grader's verdict; predictions and don't-know stay `null`.
