# 03: A big project opens as an overview of folders and modules

**What to build:** Opening the person's own projects showed that the Components layer does not scale: it draws every module as a column side by side in one long row, with all its classes, methods and functions. Telegram (209 modules, about 4,800 Nodes) is a strip of about 40,000 px of which only two modules are visible at normal zoom, and Fit shrinks it to nothing; hubstaff-automation (about 600 modules, about 15,600 Nodes) is 193,000 SVG elements. Make a project with more than 40 modules open the Components layer as an **overview**: every module is one compact box (its name, how many classes and functions it holds) grouped under the label of its folder, laid out in wrapped rows that fit the screen instead of one strip; the imports and calls between modules are merged into one line per pair (with its count and its weakest Resolution, as in the detailed view) and only the lines of the module under the pointer or selected are lit, the rest are quiet. Opening a module (double click, or Enter on it) shows the detailed view of that module only (its classes, methods and functions as today, and stubs for what leaves it), with a visible control "All modules" to go back. A project with 40 modules or fewer looks exactly as today.

**Blocked by:** None (the freeze and the build-folder problems are fixed).

**Status:** done

## Review notes

- [x] Core (`src/core/components-layout.ts`, `src/core/routes/focus.ts`): `GET /layout?layer=components` answers `mode: "overview"` for more than 40 modules (`OVERVIEW_ABOVE`) and `mode: "detail"` otherwise (the 40-or-fewer answer is the old one plus the `mode` field; checked by comparing the drawn elements of `shop`, `relations` and a 30-module project with the previous commit: identical). `layoutComponentsOverview` is pure and deterministic: modules grouped by the folder of their file (blocks `folder:<path>`, "." for the root, ordered by path; modules by name), each a 200 x 56 box with its counts (`counts[id]`, functions include methods), blocks placed in lanes of four module columns each (the lane count follows the size of the project, 2 for 120 modules, 3 for Telegram, 4 for hubstaff, so the whole is a screen shape, not a strip; a big folder spans several lanes). Routes: one per ordered pair of modules (strongest kind calls > inherits > imports, count, weakest Resolution), the strongest 400 by count, `pairs: { total, shown }`; points are `[start, control, end]` of a gentle quadratic curve between box edges. `&module=<id>` returns today's detailed layout of that module only; what leaves it to other modules is a stub labelled with the module's name, resolved ones only (inferred calls fan out to dozens of modules: one module of hubstaff had 5,800 of them); 404 for an id that is not a module.
