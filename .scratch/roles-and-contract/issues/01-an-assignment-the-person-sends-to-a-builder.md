# 01: An Assignment: the person writes it and sends it to a Builder

**What to build:** The format of an Assignment (goal in plain words, context as references to Nodes, Contract items, plugins and lessons, constraints, acceptance checks, target Builder) and the card where the person writes it, reviews it and presses Send. The kernel delivers it to the chosen Builder as its task. The Builder keeps its own permission mode and any condition in force: an Assignment never widens what a Builder may do. Nothing but the person's button sends an Assignment.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] The card has the five parts; Send is disabled until goal and target are filled.
- [ ] An Assignment sent arrives to the Builder as its task, with the references resolved to text it can read.
- [ ] No tool, role or setting sends an Assignment without the person pressing Send (a test searches the Tutor's tools for any way to).
- [ ] The Builder's permission mode is unchanged by an Assignment (a fake Builder proves it).
- [ ] Core API and page tests pass at 1920 and 1280 pixels.
